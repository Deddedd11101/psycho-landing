# Лендинг психолога: воронка записи и Telegram-бот

Готовый к деплою сайт: адаптивный лендинг, пошаговая воронка (wizard) сбора анкеты,
выбор даты и времени приёма и уведомления через Telegram-бота — специалисту и клиенту.

Бот записи: [@darwinapsybot](https://t.me/darwinapsybot).

**Стек:** React 18 + TypeScript + Vite (фронтенд), Node.js + Express / serverless-функции Vercel (бэкенд),
Telegram Bot API напрямую через `fetch` (без внешних библиотек), обычный CSS с переменными темы.
База данных не нужна: заявка живёт в памяти (или в Redis) до подтверждения в боте.

> **Что осталось заполнить перед публикацией**
>
> - Фото специалиста: положить файл в `frontend/public/sofya.jpg` (вертикальный кадр от 800×1000 px).
>   Пока файла нет, показывается заглушка.
> - Ссылка на видеовстречу (`MEETING_LINK` в `.env`) и точный адрес очного приёма (`OFFICE_ADDRESS`).
> - Раздел с отзывами появится, когда будут реальные отзывы клиентов с их согласия.
> - Стоит перевыпустить токен бота (`/revoke` у @BotFather), если он попадал в переписку.

## Что умеет проект

**Лендинг**

- Фиксированная шапка с якорной навигацией (на мобильных — бургер-меню).
- Первый экран, блоки «О психологе», «Услуги и цены», «Как проходит работа», «Принципы работы», FAQ,
  призыв к действию, подвал с политикой конфиденциальности.
- Адаптивная вёрстка mobile-first, зоны нажатия от 44–52 px, поддержка `prefers-reduced-motion`.

**Воронка записи (модальное окно)**

1. Личные данные: имя, пол, возраст, телефон (необязательно).
2. Направления работы: чекбоксы + свой вариант.
3. Свободное описание запроса (можно пропустить).
4. Сводка введённых данных + чекбокс согласия на обработку данных и выбор действия:
   «Записаться на сессию» (открывается календарь) или «Связаться с психологом в Telegram».

Плюс: индикатор прогресса, анимации переходов, валидация на каждом шаге, черновик анкеты
в `localStorage`, прелоадер во время отправки, экраны успеха и ошибки.

**Расписание**

- Свободное время приходит с сервера: занятый слот пропадает из календаря, а день,
  где заняты все слоты, не показывается вовсе.
- Слот занимается в момент отправки анкеты. Если двое выбрали одно время одновременно,
  второй получает понятное сообщение и возвращается к календарю с обновлённым расписанием.

**Telegram**

- Психолог получает заявку сразу после отправки формы — даже если клиент не дошёл до бота.
- Клиент, нажав «Start» в боте, получает подтверждение с датой, временем и контактом психолога.
- Психолог получает второе сообщение — со ссылкой на чат с клиентом (`tg://user?id=…` и `@username`).

## Как работает запись (важно понять до настройки)

Telegram-бот **не может написать человеку первым**: чтобы отправить сообщение, боту нужен `chat_id`,
а он появляется только после того, как человек сам открыл диалог с ботом. Поэтому используется
deep-link (в задании — «Способ Б»):

```
Клиент заполняет анкету на сайте
        │
        ▼
POST /api/submit-form ──► сервер создаёт заявку (sessionId)
        │                 и сразу шлёт психологу «Новая заявка»
        ▼
Сайт показывает кнопку  https://t.me/<бот>?start=<sessionId>
        │
        ▼
Клиент жмёт «Start» в боте
        │
        ▼
Бот получает «/start <sessionId>» вместе с chat_id клиента
        │
        ├──► клиенту: подтверждение (дата, время, ссылка на встречу, контакт психолога)
        └──► психологу: полная анкета + прямая ссылка на чат с клиентом
```

Заявка хранится на сервере не дольше `SESSION_TTL_SECONDS` (по умолчанию 24 часа).
Если клиент не нажмёт «Start» — психолог всё равно получил анкету на первом шаге
и может связаться по телефону, если клиент его оставил.

## Быстрый старт локально

Нужен Node.js 20 или новее.

```bash
npm install
```

```bash
cp .env.example .env
```

Заполните в `.env` хотя бы `BOT_TOKEN`, `BOT_USERNAME` и `PSYCHOLOGIST_CHAT_ID`
(как их получить — в следующем разделе), затем:

```bash
npm run dev
```

- Сайт: <http://localhost:5173>
- API: <http://localhost:3001> (Vite проксирует туда все запросы `/api/*`)
- Бот запускается в том же процессе, что и API, в режиме long-polling — так он видит
  заявки, лежащие в памяти сервера.

Проверить, что сервер поднялся и настройки прочитаны:

```bash
curl http://localhost:3001/api/health
```

Ответ `{"ok":true,"store":"memory","telegramConfigured":true}` означает, что всё готово.

### Полезные команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Фронтенд (5173) + API и бот (3001) одновременно |
| `npm run dev:web` | Только фронтенд |
| `npm run dev:server` | Только API + бот |
| `npm run dev:bot` | Бот отдельным процессом (нужен `API_BASE_URL` или Redis) |
| `npm run build` | Сборка фронтенда в `frontend/dist` |
| `npm run typecheck` | Проверка типов фронтенда и серверного кода |
| `npm start` | Express в продакшн-режиме (раздаёт `frontend/dist`) |
| `npm run bot:whoami` | Показать chat_id тех, кто писал боту (для `PSYCHOLOGIST_CHAT_ID`) |
| `npm run bot:set-webhook` | Установить вебхук Telegram на `PUBLIC_URL` |
| `npm run bot:delete-webhook` | Удалить вебхук (вернуться к long-polling) |

## Настройка Telegram-бота

**1. Создайте бота**

Для этого проекта бот уже создан — [@darwinapsybot](https://t.me/darwinapsybot), токен лежит в `.env`.
Если понадобится новый бот:

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите отображаемое имя (например, «Запись на консультацию»).
3. Введите username — обязательно заканчивается на `bot` (например, `darwinapsybot`).
4. BotFather пришлёт токен вида `1234567890:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`.
   Это `BOT_TOKEN`, а username без `@` — это `BOT_USERNAME`.

**2. Узнайте chat_id специалиста**

Специалист открывает [@darwinapsybot](https://t.me/darwinapsybot) и нажимает «Start». После этого:

```bash
npm run bot:whoami
```

Команда покажет строку вида `PSYCHOLOGIST_CHAT_ID=123456789` — скопируйте её в `.env`.

> Нажать «Start» обязательно: без этого Telegram не разрешит боту писать первым,
> и заявки приходить не будут.

**3. Необязательно, но приятно**

В BotFather: `/setdescription`, `/setabouttext`, `/setuserpic` — оформление карточки бота.
Команду `/setcommands` можно задать так:

```
start - Подтвердить заявку и получить контакт
help - Как записаться
```

**4. Проверьте**

Запустите `npm run dev`, заполните анкету на сайте, нажмите «Открыть Telegram и подтвердить»,
затем «Start» в боте. Клиенту придёт подтверждение, психологу — анкета со ссылкой на клиента.

## Переменные окружения

Полный образец — в [`.env.example`](.env.example). Кратко:

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `BOT_USERNAME` | да | Username бота без `@` — для ссылки `t.me/<username>?start=…` |
| `PSYCHOLOGIST_CHAT_ID` | да | Числовой chat_id получателя заявок |
| `PSYCHOLOGIST_USERNAME` | да | Публичный контакт психолога (без `@`) |
| `PSYCHOLOGIST_NAME` | нет | Имя специалиста в текстах бота |
| `MEETING_LINK` | нет | Ссылка на онлайн-встречу в подтверждении клиенту |
| `OFFICE_ADDRESS` | нет | Адрес очного приёма |
| `PUBLIC_URL` | нет | Публичный адрес сайта (в текстах бота и при установке вебхука) |
| `PORT` | нет | Порт Express-сервера (по умолчанию 3001) |
| `USE_POLLING` | нет | `true` локально, `false` на Vercel (там вебхук) |
| `INTERNAL_API_TOKEN` | нет | Защита служебных эндпоинтов `/api/session/:id` и `/api/booking` |
| `TELEGRAM_WEBHOOK_SECRET` | нет | Секрет, которым Telegram подписывает запросы к вебхуку |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | на Vercel — да | Общее хранилище заявок |
| `SESSION_TTL_SECONDS` | нет | Срок жизни заявки, по умолчанию 86400 (сутки) |
| `VITE_API_BASE_URL` | нет | Базовый URL API для фронтенда; пусто = тот же домен |

`.env` в git не попадает — он в `.gitignore`.

## Деплой на Vercel

**1. Загрузите репозиторий на GitHub** (см. раздел [Работа с Git](#работа-с-git)).

**2. Импортируйте проект в Vercel**

На <https://vercel.com> → *Add New* → *Project* → выберите репозиторий.
Настройки сборки Vercel возьмёт из `vercel.json`, менять ничего не нужно:

- Build Command: `npm run build`
- Output Directory: `frontend/dist`
- Функции: всё, что лежит в `api/`

**3. Добавьте хранилище заявок (обязательно)**

Serverless-функции не разделяют память между вызовами, поэтому вариант «в памяти»
на Vercel работать не будет: бот не найдёт заявку, созданную сайтом. Заведите бесплатную
базу на <https://upstash.com> (Redis → Create Database → вкладка REST API) и добавьте
в переменные окружения проекта:

```
UPSTASH_REDIS_REST_URL=https://xxx.upstash.io
UPSTASH_REDIS_REST_TOKEN=AX...
```

**4. Добавьте остальные переменные окружения**

В настройках проекта (*Settings → Environment Variables*) задайте `BOT_TOKEN`, `BOT_USERNAME`,
`PSYCHOLOGIST_CHAT_ID`, `PSYCHOLOGIST_USERNAME`, `PSYCHOLOGIST_NAME`, `MEETING_LINK`, `OFFICE_ADDRESS`,
`PUBLIC_URL` (адрес вашего сайта), `TELEGRAM_WEBHOOK_SECRET` (любая длинная случайная строка)
и `USE_POLLING=false`.

**5. Задеплойте и включите вебхук**

После первого деплоя пропишите Telegram, куда присылать апдейты. Локально, с тем же `.env`,
где `PUBLIC_URL` указывает на боевой домен:

```bash
npm run bot:set-webhook
```

Или вручную:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<ваш-домен>/api/telegram/webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

Проверить состояние вебхука: `https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo`.

## Деплой на обычный сервер (VPS)

Для этого проекта выбран именно этот вариант: сервер в РФ, бот через long-polling,
хранилище в памяти процесса — Redis и вебхук не нужны.

В папке `deploy/` лежит всё необходимое:

| Файл | Назначение |
| --- | --- |
| `deploy/setup-server.sh` | Первичная настройка чистого Ubuntu/Debian: Node 22, nginx, certbot, systemd, ufw |
| `deploy/update.sh` | Обновление после изменений в git: pull → build → restart |
| `deploy/psycho.service` | systemd-юнит (автозапуск, перезапуск при падении) |
| `deploy/nginx.conf` | nginx: статика фронтенда + прокси `/api` в Node |

**Первый запуск** (от root на сервере):

```bash
git clone https://github.com/Deddedd11101/psycho-landing.git /opt/psycho && bash /opt/psycho/deploy/setup-server.sh <домен-или-IP> https://github.com/Deddedd11101/psycho-landing.git
```

Затем положите `.env` в `/opt/psycho/.env` (в нём `PUBLIC_URL` должен указывать на адрес сайта,
`USE_POLLING=true`) и выполните `systemctl restart psycho`.

**Обновление** после `git push`:

```bash
bash /opt/psycho/deploy/update.sh
```

**HTTPS** после привязки домена (A-запись на IP сервера):

```bash
certbot --nginx -d ваш-домен.ru
```

Полезное: логи — `journalctl -u psycho -f`, статус — `systemctl status psycho`,
проверка — `curl http://localhost:3001/api/health`.

## Частые проблемы

**Бот не пишет клиенту.** Клиент должен сам нажать «Start» в боте — это ограничение Telegram.
На экране успеха для этого есть кнопка.

**Бот не пишет психологу.** Психолог тоже должен один раз нажать «Start» в боте.
Проверьте, что `PSYCHOLOGIST_CHAT_ID` — число, а не username.

**Слот остался занятым, хотя клиент не пришёл.** Слот занимается при отправке анкеты.
Освободить его можно, очистив запись в хранилище (при Upstash — ключ `psycho:booked`),
либо перезапустив сервер, если хранилище в памяти.

**«Заявка не найдена» после нажатия Start.** Либо истёк `SESSION_TTL_SECONDS`, либо на Vercel
не подключён Upstash (память между вызовами функций не сохраняется), либо сервер перезапускался.

**Ошибка 409 в логах бота.** Одновременно запущены long-polling и вебхук либо два экземпляра бота.
Выполните `npm run bot:delete-webhook` или остановите лишний процесс.

**Форма отвечает «Сервис записи временно недоступен».** Не заданы `BOT_TOKEN` или
